# Gift Radar

Telegram-бот для анализа коллекционных подарков. Покупка, продажа, кошельки и выставление лотов отсутствуют.

Реализованы расчёты по завершённым продажам, сценарии, подробные расходы и ROI, фильтры, подписи, избранное, уведомления без повторов, SQLite, команды и пошаговые кнопки. **Portals, Tonnel и MRKT пока отключены:** официальное разрешение и контракт API не подтверждены. История и лоты не выдумываются. Без реального разрешённого экспорта бот покажет отсутствие данных. Это работающая основа MVP с интерфейсом и аналитикой, а не подтверждённый живой мониторинг рынков.

Подробности: [исследование источников](docs/SOURCES.md), [архитектура и формулы](docs/ARCHITECTURE.md), [формат разрешённого экспорта](docs/EXPORT.md).

## Обновление существующего хостинга с GitHub

Репозиторий приложения: https://github.com/nalpax/my-telegram-bot1, ветка `main`. Код магазина, платежей, заказов, обязательной подписки и админ-панели заменён аналитическим Gift Radar. История прежнего кода сохранена в Git.

Если хостинг запускает `python main.py` или `python -m bot.main`, менять команду не нужно: обе точки входа теперь запускают аналитику. Старые `BOT_TOKEN` и `.env` продолжают работать. `ADMIN_IDS`, `PAYMENT_PROVIDER_TOKEN`, `DATABASE_URL` и другие магазинные настройки новым кодом не используются. Не удаляйте старую БД, PostgreSQL volume или сохранённые файлы сервера: они не переносятся в аналитику и не затрагиваются обновлением исходников.

После обновления ветки `main` дождитесь сборки хостинга или вручную выполните Redeploy/Restart с повторной установкой `requirements.txt`. В Telegram отправьте **новую команду `/start`**: появится меню Gift Radar, прежняя клавиатура магазина будет убрана. Старые сообщения и кнопки в истории Telegram сами не исчезают; нажатие старой inline-кнопки предложит открыть новое меню.

Для Docker Compose выполните `docker compose up -d --build bot`. Новому боту PostgreSQL не нужен; старый контейнер БД может остаться как orphan, его данные не удаляются. Не используйте `down -v` для обновления. Новые файлы аналитики сохраняются в `./data` на сервере. Хостинг с автоматическим перезапуском должен подхватить заменённый Dockerfile; дополнительная CA требуется только при сборке через управляемый сетевой прокси, на обычном хостинге используется стандартное доверие TLS.

Наличие нового меню не означает готовность живого мониторинга: `/markets` честно сообщает, что API площадок пока отключены. Для данных пока доступен только разрешённый экспорт; ограничения описаны ниже.

## Linux: установка и проверка

Требуется Python 3.11 или новее (совместим с прежним Dockerfile хостинга). Команды выполняются из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m gift_radar check
```

Проверка БД не обращается к рынкам и не требует токена. БД и миграции создаются автоматически в `data/radar.sqlite3`; исходные данные пусты. Повторная установка с тем же файлом зависимостей и повторное открытие БД поддерживаются.

## Windows PowerShell

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m gift_radar check
```

Активация виртуальной среды и изменение ExecutionPolicy не нужны. Код не использует Linux-only зависимости. Тесты в данной среде выполнены на Linux; отдельный запуск на Windows пока не проверен.

## Настройки и запуск Telegram

Получите токен своего бота у [BotFather](https://t.me/BotFather) и передайте `TELEGRAM_BOT_TOKEN` через секреты среды или защищённый механизм переменных окружения. Не помещайте токен в код, Git, логи, командную историю и не отправляйте его в чат. В облачной среде это требование сохранено в настройках, HTTPS-назначение `api.telegram.org`.

Приложение читает `.env` в рабочем каталоге; уже заданные переменные процесса имеют приоритет. Существующий `BOT_TOKEN` поддерживается как альтернативное имя `TELEGRAM_BOT_TOKEN`. Менять токен на хостинге не требуется. Путь `DATA_DIR` сохраняет совместимость с хостингом; новая БД — `radar.sqlite3`, старый `shop.db` не открывается. Дополнительные настройки:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `GIFT_RADAR_DB` | `data/radar.sqlite3` | Путь SQLite |
| `GIFT_RADAR_SCAN_SECONDS` | `300` | Интервал фонового цикла, не меньше 30 секунд; официальные адаптеры пока отключены |
| `GIFT_RADAR_RETENTION_DAYS` | `90` | Хранение рыночной истории, не меньше 30 дней |
| `GIFT_RADAR_LOG_DIR` | `logs` | Каталог журналов |

После настройки токена:

```bash
.venv/bin/python -m gift_radar bot
```

Перед запуском можно проверить токен и сеть без отправки сообщений: `.venv/bin/python -m gift_radar telegram-check`. Команда выполняет только `getMe` и не выводит токен или имя бота.

На Windows используйте `.venv\Scripts\python.exe -m gift_radar bot`. Нужен HTTPS-доступ к `api.telegram.org`; webhook, публичный порт и доступ к кошельку не требуются. В управляемой среде сохраняйте унаследованный HTTPS-прокси и CA; проверки TLS не отключать. Не запускайте несколько polling-процессов с одним токеном.

Откройте своего бота и отправьте `/start`. Меню: `/help`, `/settings`, `/markets`, `/scan`, `/alerts`, `/favorites`, `/fees`, `/currency`, `/status`. Настройки через кнопки и один короткий ввод за раз; `/cancel` отменяет ввод. `/delete_me` с подтверждением удаляет персональные настройки, избранное, скрытые лоты, личные курсы и историю уведомлений.

1. Проверьте `/markets`: все неподтверждённые площадки отображаются отключёнными.
2. Если располагаете разрешённым реальным экспортом, импортируйте его по [схеме](docs/EXPORT.md), затем `/scan` покажет аналитические карточки. Не полагайтесь на них как на полный снимок рынка.
3. Настройте расходы для каждой пары площадок и валюты через `/fees`. Все расходы неизвестны по умолчанию. Явный 0 только для неприменимого сбора. Ручные суммы помечаются пользовательскими.
4. Настройте валюту порогов, фильтры и при необходимости курсы; без курса конвертация недоступна. Меняя валюту порогов, вручную проверьте значения порогов — они не конвертируются автоматически.
5. Включите `/alerts`. Уведомления требуют достаточных аналогов, уверенности не ниже средней, полного расчёта, свежих комиссий и лота не старше 30 минут. `/scan` также показывает неполные расчёты; экономические фильтры применяются к уведомлениям.

Кнопки карточки: открыть реальную ссылку (если есть), сравнить площадки, посмотреть аналоги/происхождение свойств, добавить в избранное, скрыть лот. В журнал не выводятся URL запросов или тексты сетевых ошибок с секретами. При неопределённой доставке уведомление не повторяется автоматически, поэтому возможен пропуск сообщения; это выбранная защита от дублей.

Реальный курс можно настроить оператором из своего законного источника: `python -m gift_radar rate TON USD <фактический_курс> --source <реальный_источник> --at <ISO_время_с_поясом>`. Значения в угловых скобках заменяются фактическими; в проекте нет демонстрационного курса. Пользовательский курс через `/currency` действует только для этого пользователя и помечается ручным. Курсы действуют один час.

## Постоянный сервер Linux

Запуск только на компьютере разработчика не обеспечивает непрерывную работу. Для сервера разместите проект, например в `/opt/my-telegram-bot1`, установите зависимости в его `.venv`, создайте отдельного пользователя `gift-radar` и предоставьте ему право писать в каталоги `data` и `logs`. Это действия администратора сервера, они не выполнялись в облачной среде.

В [deploy/gift-radar.service](deploy/gift-radar.service) приведён unit systemd. Проверьте пути и пользователя. Секреты передайте через защищённый `/etc/gift-radar.env` с правами чтения только нужных администраторов; unit читает его через `EnvironmentFile`. Скопируйте unit в каталог systemd и выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gift-radar
sudo systemctl status gift-radar
```

Проверьте ответ на `/status`, содержимое `logs/radar.log` и состояние источников в `/markets`. Для остановки — `sudo systemctl stop gift-radar`; при ручном запуске — Ctrl+C. Фоновая задача отменяется, соединения закрываются. systemd-конфигурация предоставлена для самостоятельного развёртывания, её работа на отдельном сервере здесь не проверена.

## Проверки и границы готовности

`python -m pytest -q` проверяет расчёты, подбор аналогов, подпись, комиссии, курсы, неизвестные расходы, фильтры, SQLite, дедупликацию, фоновые уведомления и Telegram-команды через искусственный транспорт. Весь искусственный материал находится только в тестах. `python -m gift_radar check` проверяет БД, количество записей, состояние источников и наличие токена без раскрытия его значения. Это не проверка токена через Telegram.

Живые запросы Telegram и площадок пока не проверены. Для завершения подключения нужны: токен Telegram в секретах, применённые сетевые настройки и подтверждённые официальные источники с условиями использования, лимитами и схемой ответов. До этого нельзя считать непрерывный мониторинг рынков готовым. Опубликовать подготовленную облачную среду можно через настройки после просмотра и сохранения черновика; публикация и запуск в новой задаче пока не выполнены.
