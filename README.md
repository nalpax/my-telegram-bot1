# Telegram Shop Bot

Полноценный Telegram-магазин цифровых товаров с админ-панелью, управляемой
полностью через Telegram — без изменения кода после запуска.

Стек: **aiogram 3** (async), **PostgreSQL** + **SQLAlchemy 2.0 (async)**,
**Docker Compose**.

## Возможности

- Каталог: категории → товары → покупка, постраничная навигация
- 🔍 Поиск по названию и описанию (регистронезависимый, в т.ч. кириллица), ⭐ избранное
- 💬 Раздел «Поддержка» и /help, контакт поддержки и текст приветствия
  настраиваются из админки
- 🎁 Промокод на 100% — товар выдаётся сразу, без оплаты; каждый промокод
  действует один раз на покупателя
- ↩️ При оплате в Telegram Stars, если товар закончился в последний момент,
  деньги возвращаются автоматически
- 🔑 Купленный товар навсегда сохраняется в «Мои заказы» — даже если
  админ позже удалит товар или категорию
- Продажа цифровых позиций (ключи/аккаунты/коды) — по одной на покупателя,
  выдаётся только после подтверждённой оплаты (Telegram Payments или Stars)
- 🔒 Обязательная подписка на канал (опционально): пока пользователь не
  подписан, доступ к магазину закрыт; проверка идёт через Telegram API
  (`getChatMember`), а не по факту нажатия кнопки. Канал настраивается через
  админ-панель без изменения кода — бот должен быть добавлен в канал
  администратором, иначе Telegram не отдаёт статус подписки
- Единые статус-индикаторы по всему боту: 🟢 включено, 🔴 выключено,
  ⚪ не настроено, 🟡 мало в наличии
- Админ-панель (доступ только по ID из `.env`):
  - категории: добавление, переименование, описание, вкл/выкл, порядок, фото
  - товары: добавление (пошагово), название/описание/цена/категория/статус,
    фото, цифровые позиции, удаление
  - промокоды: скидка %, срок действия, лимит использований
  - статистика: продажи за сегодня / 7 / 30 дней, топ товаров,
    заканчивающиеся позиции
  - заказы с карточкой заказа (покупатель, что выдано, отметка возврата)
  - 👥 пользователи: поиск по ID или @username, блокировка/разблокировка
  - рассылка с предпросмотром: текст, фото, видео, файлы с форматированием
  - уведомления админам о каждой продаже и о заканчивающемся товаре
  - цифровые позиции можно загружать несколькими сообщениями или .txt-файлом
  - обязательная подписка на канал — включение/выключение, смена канала
  - фото каталога, категорий и товаров — только загружаются вручную через
    Telegram, в проекте никаких готовых изображений нет
- FSM для всех пошаговых операций, с отменой на каждом шаге
- Все данные — в SQLite (файл в `DATA_DIR`) или PostgreSQL (если задан
  `DATABASE_URL`), ничего не теряется при перезапуске
- Подтверждение перед любым удалением
- Бот не падает при ошибках ввода, БД или Telegram API — все обрабатывается
  и логируется, а пользователь видит понятное сообщение вместо «вечной» кнопки
- Весь пользовательский текст экранируется — символы `<`, `>`, `&` в названиях,
  ключах и описаниях не ломают сообщения
- Оплаты, пришедшие пока бот был выключен, обрабатываются после запуска

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
   - `ADMIN_IDS` — ваш Telegram ID (узнать можно у [@userinfobot](https://t.me/userinfobot))
   - `PAYMENT_PROVIDER_TOKEN` — токен платёжного провайдера от BotFather
     (Payments). Если хотите продавать за **Telegram Stars**, оставьте это
     поле пустым и укажите `CURRENCY=XTR`.

2. Запустите:

   ```bash
   docker compose up -d --build
   ```

   Бот сам создаст таблицы в базе при первом запуске.

3. Откройте бота в Telegram, отправьте `/start` (обычное меню) или `/admin`
   (админ-панель, если ваш ID указан в `ADMIN_IDS`).

## Структура проекта

```
bot/
  config.py            # настройки из .env
  main.py              # точка входа, регистрация роутеров и middleware
  middlewares.py        # сессия БД, регистрация пользователя, ловля ошибок
  database/
    models.py           # User, Category, Product, DigitalItem, Order, PromoCode, Setting
    engine.py            # async-движок, создание таблиц
    repo.py              # все операции с БД
  states/states.py       # FSM-состояния
  keyboards/              # инлайн-клавиатуры (user.py, admin.py)
  filters/admin.py         # серверная проверка прав администратора
  handlers/
    user/                  # каталог, заказы, профиль, /start
    admin/                  # категории, товары, позиции, промокоды, рассылка, статистика, настройки
    payments.py               # pre_checkout_query + successful_payment
  utils/                       # форматирование, логирование, рендер экранов
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты используют временную SQLite-базу и поддельный Telegram API, прогоняют
через настоящий диспетчер покупку за Stars, возврат, бесплатный промокод,
обязательную подписку, блокировку и все экраны админ-панели.

## Первые шаги в боте (администратор)

1. `/admin` → 📦 Товары → ➕ Добавить категорию
2. Откройте категорию → ➕ Добавить товар → название → описание → цена → фото
3. В карточке товара → 📦 Позиции → ➕ Добавить позиции → отправьте ключи,
   каждый с новой строки (или .txt-файлом), затем «✅ Готово»
4. Товар автоматически появится в каталоге для пользователей
5. ⚙️ Настройки → 💬 Контакт поддержки — чтобы покупателям было куда писать

Цены: `/admin` → 💰 **Цены** — все товары одним списком, нажмите на товар и
отправьте новую цену («199», «199.90», «1 500 руб» — всё понимается).
Также кнопка «💰 Изменить цену» есть прямо в карточке товара.

Пока платёжка не подключена (пустой `PAYMENT_PROVIDER_TOKEN` и валюта не
`XTR`), бот работает как витрина: при нажатии «Купить» покупатель видит
«Онлайн-оплата скоро будет доступна» и контакт поддержки.

## Платежи

Используется нативный Telegram Payments API (`send_invoice` /
`pre_checkout_query` / `successful_payment`). Цифровая позиция выдаётся
**только** после `successful_payment` и атомарной блокировки одной свободной
позиции в БД (process-wide lock, а на PostgreSQL ещё и
`SELECT ... FOR UPDATE SKIP LOCKED`) — два одновременных покупателя никогда
не получат один и тот же ключ. Перед оплатой (`pre_checkout_query`)
проверяются владелец заказа, сумма, валюта и наличие. Если позиции
закончились уже после оплаты, заказ помечается `failed`; оплата в Stars
возвращается автоматически, а при оплате картой все администраторы получают
уведомление для ручного возврата (отметить его можно в карточке заказа).

При повторном нажатии «Купить» старый неоплаченный счёт аннулируется, так
что оплатить устаревшую цену нельзя.

## Хранилище состояний FSM

По умолчанию используется `MemoryStorage` (состояния сбрасываются при
перезапуске бота, что не критично — это только временные пошаговые формы
администратора). Для продакшена с несколькими воркерами замените на
`RedisStorage` из `aiogram.fsm.storage.redis`.

## Примечание про фотографии

Бот хранит только `file_id` от Telegram — сами файлы не скачиваются и не
хранятся на сервере. Никаких изображений в репозитории нет и не будет:
всё загружается вами через кнопки «Фото» в админ-панели.
