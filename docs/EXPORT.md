# Разрешённый экспорт: внутренний формат

Это формат нашего приложения, **не** формат API Portals/Tonnel/MRKT. Приведение реального разрешённого экспорта выполняется отдельно после проверки источника и прав. Не загружайте искусственные сделки в рабочую БД. В проекте нет демонстрационного экспорта и нет URL для выдуманного API.

Корневой JSON-объект:

| Поле | Значение |
|---|---|
| `schema_version` | 1 |
| `source` | Реальное название и происхождение экспорта; не секрет |
| `listings` | Массив нормализованных лотов, допустим пустой |
| `sales` | Массив завершённых продаж, допустим пустой |

Каждый лот:

| Поле | Тип / правило |
|---|---|
| `market` | `portals`, `tonnel` или `mrkt` |
| `listing_id`, `name` | Непустая строка, ID из источника |
| `price` | Положительная десятичная строка, до 10¹⁵ |
| `currency` | `TON`, `USD`, `RUB`; другие валюты пока не поддерживаются |
| `updated_at` | ISO 8601 с часовым поясом, реальное время обновления, не будущая дата |
| `url` | Реальная публичная HTTPS-ссылка или `null`; не ссылку с токенами/авторизацией |
| `collection`, `model`, `backdrop`, `pattern`, `symbol` | Строка или `null`, никаких предположений по названию |
| `serial` | Положительное целое число или `null` |
| `rare`, `signature` | `true`, `false` или `null` |
| `signature_text` | Строка или `null`; текст допустим только при `signature=true` |
| `listed_at` | Реальное время размещения с часовым поясом или `null` |
| `status` | `active`, `sold`, `withdrawn` |
| `provenance` | Объект: для каждого известного свойства выше — источник этого свойства. Например путь поля в реальном экспорте/ссылка документации. Неизвестное свойство не заполнять |
| `raw` | Объект разрешённых исходных данных для диагностики; без ключей, авторизации, кошельков и лишних персональных данных |

Поле `source` лота при импорте берётся из корня файла, даже если внутри указано другое. Для начала оценки необходимы известные коллекция и модель; неизвестные подпись/редкость/узор/символ/номер снижают уверенность и не дают уведомлений.

Каждая завершённая продажа: `sale_id` (ID **сделки**, а не ID объявления), `gift` (лот со статусом `sold`, цена — **фактическая цена продажи**), `sold_at` (фактическое время продажи с часовым поясом), `evidence` (описание доказательства завершённой сделки/ссылка источника). Время размещения не позже продажи, время продажи не из будущего. Снятый лот не считается проданным. Для ссылки на источник продажи используйте `gift.url`.

Чтение проверяет весь файл до записи в БД; при любой ошибке файл не импортируется. Максимальный размер 10 MiB, по 10000 записей в каждом массиве. Идентичный импорт не создаёт дублей. Новая цена лота требует нового `updated_at`. Если export частичный, отсутствие лота не считается снятием; передайте его реальный статус отдельной записью. Не заменяйте время исходных данных временем импорта для прохождения фильтра свежести.

```bash
python -m gift_radar import /path/to/authorized-export.json --authorized
python -m gift_radar check
```

CLI сообщает только категории ошибки, не содержимое файла: проверьте схему и метаданные локально. Пока нет автоматических адаптеров, новые данные поступают только через явный импорт; приложение не обещает непрерывный мониторинг рынков.
